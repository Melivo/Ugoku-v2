## PR-Cache-Isolation

### Plattformbefund

act_runner v0.2.11 verwendet `gitea/act v0.261.2/pkg/artifactcache`.

- Offizieller Quellcode: `TODO: Authorization`.
- Offizieller Quellcode: `TODO: Restrictions for accessing a cache`.
- Cachemodell enthält nur ID, Key, Version, Größe und Zeitstempel; keinen Repo-/Ref-/PR-Scope.
- Restore sucht global nach Key/Version und Präfix.

Damit bietet diese Version **keine native PR-Isolation**. Der bisherige Restore-Präfix `npm-` kann prinzipiell von einem PR erzeugte Einträge an `main` oder Release liefern.

### Lokale minimale Korrektur

- CI: `npm-pr-<PR-Nr>-<Lockhash>` für Pull Requests; `npm-trusted-<Lockhash>` für `main`.
- CI-Restore-Präfix entsprechend PR-spezifisch bzw. `trusted`.
- Release: ausschließlich `npm-trusted-<Lockhash>` und `npm-trusted-`.
- Keine Runner-/IAM-/Dateirechte geändert.
- Regressionstest ergänzt.

**Handoff für Tasks 3–4:** Da `jdx/mise-action@v2` keinen kontrollierten PR-Key-Namespace bereitstellt, darf der mise-Cache im CI nicht für `pull_request` aktiviert werden. Empfohlen: `cache: ${{ github.event_name != 'pull_request' }}` in CI; `cache: true` im Release-Workflow.
