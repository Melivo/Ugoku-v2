# QNAP MCP Assistant User Auth Contract

> Generated by PM Agent | Session: 20260629-qnap-mcp-assistant-user-auth | Date: 2026-06-29

## Contract Type

This is an MCP/client integration contract, not a Pro Select HTTP REST API.

Primary target: official QNAP MCP Assistant connected to `https://nasproselect.myqnapcloud.com/` with per-user QNAP authentication.

Fallback target: a thin Pros MCP policy wrapper only if the official assistant cannot provide required client compatibility, preview/approval behavior, or safe tool filtering.

## Authentication

- Each internal user authenticates with their own QNAP user credentials.
- QNAP user permissions are the primary NAS authorization boundary.
- Credentials or session tokens must not be stored in repo files, chat logs, client config, runtime artifacts, or plan artifacts.
- Preferred storage is the official QNAP MCP Assistant credential mechanism if it is per-user and local. If unavailable or unsafe, use OS Credential Store with a target pattern such as `pros:qnap-assistant:<profileId>:<userId>`.
- The initial endpoint to validate is `https://nasproselect.myqnapcloud.com/`.

## Capability Contract

### qnap_status

- Description: Check assistant connectivity, authenticated user, NAS endpoint, and redacted capability summary.
- Auth: Required per-user QNAP auth.
- Input:
  ```json
  {
    "profileId": "string (optional)"
  }
  ```
- Output:
  ```json
  {
    "status": "ready | needs-auth | needs-admin | failed",
    "endpoint": "https://nasproselect.myqnapcloud.com/",
    "user": "redacted or display-only username when safe",
    "capabilities": ["list", "read", "download", "upload", "delete-preview"],
    "message": "string"
  }
  ```
- Errors: auth missing/expired, endpoint unreachable, assistant unavailable.

### qnap_list

- Description: List files/folders visible to the authenticated QNAP user.
- Auth: Required; QNAP permissions decide visibility.
- Input:
  ```json
  {
    "remotePath": "string"
  }
  ```
- Output:
  ```json
  {
    "items": [
      {
        "name": "string",
        "path": "string",
        "type": "file | folder",
        "sizeBytes": 123,
        "modifiedAt": "ISO-8601 string"
      }
    ]
  }
  ```
- Errors: forbidden by QNAP, path not found, auth expired.

### qnap_search

- Description: Search files/folders visible to the authenticated QNAP user.
- Auth: Required.
- Input:
  ```json
  {
    "query": "string",
    "remotePath": "string (optional root/folder scope)"
  }
  ```
- Output: Same item summary shape as `qnap_list`.
- Errors: forbidden by QNAP, assistant search unsupported, auth expired.

### qnap_download_preview

- Description: Prepare a download plan without transferring data.
- Auth: Required.
- Input:
  ```json
  {
    "remotePath": "string",
    "localPath": "string",
    "overwrite": false
  }
  ```
- Output:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string",
    "remotePath": "string",
    "localPath": "string",
    "overwrite": false,
    "impact": "download only; no NAS mutation"
  }
  ```

### qnap_download_approved

- Description: Execute a previously previewed download after explicit user approval.
- Auth: Required.
- Input:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string"
  }
  ```
- Output:
  ```json
  {
    "status": "completed",
    "localPath": "string",
    "remotePath": "string"
  }
  ```

### qnap_upload_preview

- Description: Prepare an upload/overwrite/edit plan without mutating the NAS.
- Auth: Required; QNAP write permissions decide whether the operation can eventually succeed.
- Input:
  ```json
  {
    "localPath": "string",
    "remotePath": "string",
    "overwrite": false
  }
  ```
- Output:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string",
    "remotePath": "string",
    "localPath": "string",
    "overwrite": false,
    "impact": "NAS write; requires explicit approval"
  }
  ```

### qnap_upload_approved

- Description: Execute a previously previewed upload/overwrite after explicit user approval.
- Auth: Required.
- Input:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string"
  }
  ```
- Output: completion status with redacted operational details.

### qnap_delete_preview

- Description: Prepare a delete plan without deleting anything. This is allowed only if the official assistant exposes delete and the authenticated QNAP user has rights.
- Auth: Required.
- Input:
  ```json
  {
    "remotePath": "string"
  }
  ```
- Output:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string",
    "remotePath": "string",
    "impact": "destructive NAS delete; requires explicit approval"
  }
  ```

### qnap_delete_approved

- Description: Execute a previously previewed delete after explicit user approval.
- Auth: Required.
- Input:
  ```json
  {
    "previewId": "string",
    "approvalToken": "string"
  }
  ```
- Output: completion status with redacted operational details.
- Mandatory rule: no delete tool may execute without a prior preview object and matching approval token.

## Forbidden Or Gated Operations

- No silent delete.
- No silent overwrite.
- No user/group management through normal user workflows.
- No shared-folder permission changes through normal user workflows.
- No firmware, app, storage pool, snapshot, QVR, system log, or NAS admin actions through normal user workflows unless a separate admin-pilot plan approves them.
- No token/session output in tool responses.

## Acceptance

- The official assistant can be used directly only if the client configuration can expose the required safe behavior.
- If the assistant exposes destructive tools without preview/approval controls, add a thin Pros wrapper/filter or block those tools from OpenCode/AnythingLLM configuration.
