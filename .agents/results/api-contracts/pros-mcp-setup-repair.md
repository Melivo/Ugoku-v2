# Pros MCP Setup Repair Boundary Contract

> Generated by PM Agent | Session: pros-mcp-setup-repair-20260707 | Date: 2026-07-07

## Contract Type

This is a CLI/MCP/setup boundary contract, not a Pro Select HTTP REST API.

The repaired behavior spans:

- Pros CLI commands executed in PowerShell on Windows.
- OpenCode Desktop and AnythingLLM MCP client configuration.
- OS Credential Store targets used by Pros-managed integrations.
- External identity/service boundaries for Azure AD Microsoft Graph OAuth, QNAP MCP Assistant, and HubSpot OAuth.

## Authentication And Secret Handling

- Gitea release access remains controlled by existing Pros auth token handling.
- Microsoft Graph uses delegated OAuth with `PROS_MICROSOFT_CLIENT_ID`, optional `PROS_MICROSOFT_TENANT_ID`, optional `PROS_MICROSOFT_REDIRECT_URI`, and OS Credential Store token persistence.
- QNAP MCP Assistant token is stored only through the Pros-managed credential target `pros:qnap:mcp-assistant` unless a later approved migration changes that target.
- HubSpot credentials remain stored through the existing Pros-managed HubSpot credential flow.
- No secrets may be written to OpenCode config, AnythingLLM config, repo files, plan artifacts, logs, or chat.

## CLI Boundary Commands

### `pros init [--force] [--release <tag>]`

- Description: Download, verify, extract, and install Pros runtime bundle into a workspace.
- Auth: Requires configured Gitea token for release install; may use local init fallback without token in development contexts.
- Input: Current workspace path may contain spaces and non-ASCII characters.
- Required behavior: Windows archive extraction must populate the intended destination or fail loudly before manifest verification.
- Success response: Exit `0`, message includes initialized version, release tag, installed file count, and desktop asset summary.
- Error responses: Checksum mismatch, unsafe archive entry, extraction failed, manifest verification failed with actionable context.

### `pros integrations auth microsoft-graph start`

- Description: Prepare Microsoft Graph delegated OAuth PKCE URL.
- Auth: Requires valid Azure AD app client id via environment or documented configuration path.
- Input: `PROS_MICROSOFT_CLIENT_ID`; optional `PROS_MICROSOFT_TENANT_ID`; optional `PROS_MICROSOFT_REDIRECT_URI`.
- Required behavior: OAuth URL must use documented redirect URI and must surface missing or obviously invalid configuration before users reach confusing downstream states where feasible.
- Success response: Exit `0`, redaction-safe authorization URL, scopes, state, and session id.
- Error responses: Missing client id, invalid redirect/config shape, session write failure.

### `pros integrations graph status [profileId]`

- Description: Report redacted Microsoft Graph readiness.
- Auth: Requires stored delegated token or refreshable credential.
- Required behavior: Distinguish missing client id, missing credential, invalid/expired token, forbidden tenant/app, and Graph API failure where observable.
- Success response: `ready-read` or `ready-business-write-safe` as applicable.
- Error responses: `needs_credential`, `failed`, throttled, unauthorized, forbidden.

### `pros mcp qnap token set --stdin`

- Description: Store QNAP MCP Assistant bearer token in the Pros-managed OS Credential Store target.
- Auth: User supplies token through terminal stdin only.
- Input: Secret token bytes ending by EOF or piped input.
- Required behavior: UX must make stdin/EOF behavior unambiguous and must not appear as a silent hang in intended usage documentation or tests.
- Success response: Exit `0`, redacted message confirming credential stored.
- Error responses: Empty stdin, credential store unavailable, credential store write failure.

### `pros mcp qnap token status`

- Description: Report whether the Pros-managed QNAP MCP Assistant token is present.
- Auth: Reads only credential metadata/secret presence from OS Credential Store.
- Required behavior: Check the exact Pros-managed target; documentation must not instruct users to manually store under NAS URL unless code explicitly supports it.
- Success response: `ready` with secret redacted.
- Error responses: `needs_credential`, credential store unsupported/failure.

### `pros mcp configure <opencode|anythingllm> --include <server>`

- Description: Write Pros-managed MCP client entries without storing secrets in client config.
- Auth: Requires credentials only for integrations that need local wrappers at configure time.
- Servers: `hubspot`, `microsoft-graph`, `qnap-mcp-assistant`.
- Required behavior: Preserve non-Pros-managed entries, write only expected Pros-managed keys, and report missing credentials before writing dependent entries.
- Success response: status `ready`, client path, changed flag, redaction-safe messages.
- Error responses: unsupported client, invalid include, missing credential, unsafe existing secret-like config.

## MCP Runtime Boundaries

### `microsoft-graph`

- Local command: `pros-mcp-microsoft-graph` or documented compatibility alias.
- Client config must not contain tokens, refresh tokens, auth codes, or client secrets.
- Tool surface remains delegated-user only; direct send/delete/raw Graph requests remain forbidden.

### `qnap-mcp-assistant`

- Local command: `pros-mcp-qnap-assistant`.
- Remote target: `https://nasproselect.myqnapcloud.com:8443/sse` unless a later approved config changes it.
- Wrapper reads token from Pros-managed OS Credential Store and passes it to `mcp-remote` without logging it.
- Destructive operations remain gated by QNAP permissions and any existing preview/approval policy from the QNAP plan.

### `hubspot`

- Local command: `pros-mcp-hubspot-remote`.
- Existing credential behavior remains compatible.
- Repair scope is documentation/runtime guidance unless implementation tests show a regression.

## Acceptance Gates

- Windows `pros init` succeeds in a workspace path containing spaces and fails loudly if extraction yields no files.
- Microsoft Graph setup docs, CLI output, and OAuth defaults agree on redirect URI and client-id source.
- QNAP token setup has deterministic tests for stdin success, empty stdin failure, credential target status, and documented invocation.
- OpenCode and AnythingLLM MCP config tests confirm no secrets in client config and no unrelated entries removed.
- Runtime docs and workflow text match the repaired commands.
- Security review confirms no new secret leakage path.
