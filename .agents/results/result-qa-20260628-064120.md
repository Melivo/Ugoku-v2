### HIGH

- `packages/pros-cli/src/microsoft-graph.ts:810` — Attachment “MIME validation” is only an extension-to-MIME lookup. `addEmailDraftAttachment` later reads and uploads the entire file using that inferred `contentType` (`packages/pros-cli/src/microsoft-graph.ts:1477-1485`). A binary/script/archive renamed to `report.pdf` or `image.png` passes policy if it is under 2.5 MB, violating the required extension + MIME + denylist enforcement. — Remediation:

  ```ts
  // Validate content before upload; do not infer MIME solely from extension.
  async function validateGraphAttachmentFile(filePath: string, sizeBytes: number) {
    const extensionResult = validateGraphAttachmentPolicy(filePath, sizeBytes);
    if (!extensionResult.allowed) return extensionResult;

    const bytes = await readFile(filePath);
    const actualMime = detectAllowedMimeFromMagic(bytes, extensionResult.extension);
    if (actualMime !== extensionResult.contentType) {
      return {
        allowed: false,
        status: "forbidden-operation" as const,
        message: "Attachment content does not match the allowlisted MIME type.",
        extension: extensionResult.extension,
        contentType: actualMime,
      };
    }
    return { ...extensionResult, bytes };
  }
  ```

  Add tests that write an executable/archive payload to an allowlisted filename (for example `payload.pdf`) and assert `forbidden-operation` with no Graph upload call.

### MEDIUM

- `packages/pros-cli/src/microsoft-graph.ts:936` — `graphWrite` reads stored credentials and immediately performs `POST`/`PATCH` without checking that the stored scopes include `GRAPH_BUSINESS_WRITE_SCOPES`. Update/draft/attachment helper flows can also perform preliminary Graph reads before any write-scope decision. This violates the contract that write tools require `business-write-safe` authorization and creates unnecessary outbound calls with insufficiently scoped credentials. — Remediation:

  ```ts
  function requireBusinessWriteScopes<T>(
    credentialTarget: string,
    scopes: readonly string[],
  ): MicrosoftGraphWriteResult<T> | undefined {
    if (hasScopes(scopes, GRAPH_BUSINESS_WRITE_SCOPES)) return undefined;
    return {
      success: false,
      status: "needs-reauth",
      message: "Microsoft Graph write operation requires business-write-safe delegated scopes.",
      credentialTarget,
    };
  }

  // Call after confirmation and before any Graph GET/POST/PATCH in every write helper.
  const stored = readStoredMicrosoftCredential(options);
  const scopeFailure = requireBusinessWriteScopes<T>(stored.credentialTarget, stored.credential.scopes);
  if (scopeFailure) return scopeFailure;
  ```

  Add regression tests where credentials contain only `User.Read`, `Mail.Read`, `Calendars.Read`, `Files.Read`; assert no fetch call for every write helper.

- `packages/pros-cli/src/microsoft-graph.ts:1453` — Draft total attachment size is calculated only from the first `$top=50` attachment page. If a draft has more than 50 existing attachments, later pages are ignored and the 10 MB total policy can be bypassed. — Remediation:

  ```ts
  // Either page until complete within a strict max-page cap, or fail closed when nextLink exists.
  const attachments = await graphGetAttachmentsWithNextLink(...);
  if (attachments.nextLink) {
    return {
      success: false,
      status: "forbidden-operation",
      message: "Cannot verify draft attachment total size because Graph returned more pages.",
      credentialTarget,
    };
  }
  ```

  Add a mocked Graph response with `@odata.nextLink` and assert fail-closed behavior before upload.
